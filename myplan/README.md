# 1111-DIC 專案研究計畫
## 智慧菜價短期預測與資料驅動決策支援

> 本文件依據 1111-DIC 專案目前可見的對話與研究脈絡整理。本文區分已明確提及的研究內容與待補充事項；未經來源確認的硬體、感測器、資料來源、模型細節及系統功能，不視為既有成果。

## 1. 專案定位與研究目標

本專案聚焦於極端氣候事件下蔬菜價格的短期變動，以及零售端價格預測問題。研究核心不是單純以市場平均價格推估所有店家的售價，而是處理批發市場價格訊號與個別零售店實際價格之間的差異，並建立可供使用者查詢與決策的預測支援流程。

主要目標：
1. 分析颱風等極端氣候事件對蔬菜批發價格及短期零售價格的影響。
2. 釐清批發均價、公開市場資訊與個別零售店價格之間的代表性落差。
3. 以真實店家價格作為重要觀測錨點，評估短期價格變動預測的可行性。
4. 建立 AI Agent 負責互動、ForecastEngine 負責計算的系統分工。
5. 以基線模型及實驗指標檢驗預測模型是否帶來實質改善。

## 2. 研究背景與問題定義

專案研究脈絡指出，颱風後第一週蔬菜批發均價平均可能上漲約 10%–40%。然而，批發市場平均漲幅不等於每一家零售店都會同步調價。短期零售菜價呈現「多數持平、少數大變」的分布特徵，因此單一公開均價未必能代表個別店家的實際價格變化。

核心研究問題：
- 如何區分批發端價格衝擊與零售端實際調價？
- 如何處理零售價格中大量持平、少數劇烈變動的類別不平衡現象？
- 如何避免尚未成熟或跨界樣本造成評估偏差？
- 模型是否能在適當基線之上，提供可量化且穩定的預測增益？

## 3. 研究缺口與研究切入點

1. **平均值代表性不足：** 批發均價變化不能直接視為個別零售店的價格變化。
2. **零售價格分布不均：** 多數價格可能維持不變，少數樣本出現較大幅度變動；只看整體誤差可能掩蓋上漲事件辨識能力。
3. **樣本品質與時間界線：** 跨界或尚未成熟樣本可能影響訓練與測試結果，資料清理及時間切分必須明確。
4. **基線比較必要：** 必須與動量基線等簡單方法比較，才能判斷複雜模型是否真正增加預測價值。
5. **預測與互動應分層：** 對話式 Agent 不應取代可測試、可重現的數值計算核心。

## 4. 系統概念架構

目前專案資料已明確提出的分工為：AI Agent 作為使用者互動介面，ForecastEngine 作為預測與計算核心，並以真實店價作為重要資料錨點。

    使用者
      |
      v
    AI Agent（問題理解、參數蒐集、結果解說）
      |
      v
    ForecastEngine（資料處理、特徵與預測計算、基線比較）
      |
      +---- 真實店家價格資料（價格錨點）
      |
      +---- 批發市場／氣候事件等研究資料（實際欄位與來源待確認）
      |
      v
    預測結果、評估指標與不確定性說明
      |
      v
    AI Agent 回覆使用者

模組責任：
- **AI Agent：** 接收自然語言問題、整理必要條件、呼叫計算流程，並將結果轉換為可理解的說明。Agent 不應自行編造預測數值。
- **ForecastEngine：** 執行可重現的資料處理、預測、基線比較及評估；應能以固定輸入重現相同結果。
- **資料層：** 保存真實店家價格及研究所需的其他資料。批發、氣候或事件資料的實際來源、欄位、更新頻率與授權狀態，仍需以專案資料文件確認。
- **評估層：** 分別檢視整體誤差、價格持平情形及價格上漲事件辨識能力，避免單一指標造成誤判。

## 5. 研究方法與實驗設計

### 5.1 資料處理
- 檢查價格資料的時間順序、缺漏、重複及異常值。
- 明確界定預測時間點與可用資料範圍，避免將預測時點之後才取得的資訊帶入模型。
- 對跨界或尚未成熟樣本採取一致的排除或標記規則，並保留可追溯的清理紀錄。
- 以真實店家價格作為零售端分析的重要錨點。

### 5.2 預測與基線
- 建立短期價格變動預測流程。
- 與動量基線比較，確認模型是否優於簡單且可解釋的方法。
- 將價格持平與價格上漲／下跌視為需要分開觀察的結果面向。
- 模型種類、特徵清單、預測視窗及超參數設定，應以完整實驗紀錄補充；目前可見脈絡不足以確認全部細節。

### 5.3 評估
研究文件應完整記錄資料切分方式與時間範圍、各類別樣本數及比例、整體預測誤差、價格持平比例、上漲事件 Precision／Recall／F1、與動量基線的差異，以及不同事件期間或商品類別的穩健性分析。

## 9. 研究風險與限制

1. **資料代表性：** 店家、商品、地區及時間範圍可能限制研究結果的外部效度。
2. **類別不平衡：** 大量持平樣本可能使整體準確率或平均誤差看似良好，卻無法辨識少數上漲事件。
3. **時間洩漏：** 若未嚴格依時間切分資料，可能高估模型表現。
4. **基線競爭力：** 若模型未優於動量基線，需重新檢視特徵、預測目標、樣本品質及評估設計。
5. **事件外推限制：** 颱風事件的影響可能因品項、地區、供應鏈及事件強度而異，不宜將單一平均值套用到所有零售店。
6. **系統與研究成果區分：** Agent 能成功回覆，不代表預測模型有效；介面完成度與預測效能應分開驗證。
